# Job Application Assistant

Paste or upload a resume and a job posting, and get back a match score, a
skills gap breakdown, and a tailored cover letter — generated by an LLM via
[Groq](https://groq.com/).

## Features

- **Match score** — 0–100 fit score with matched/missing skills, color-coded
  by tier.
- **Resume input** — paste text or upload a PDF/DOCX/TXT file.
- **Job posting input** — paste text, paste a URL (the page is scraped
  automatically), or upload a file.
- **Tailored cover letter** — generated in the tone you pick (professional,
  formal, conversational, enthusiastic), fully editable before export.
- **Export** — download the cover letter as a PDF or a Word document.
- **Responsive UI** — works across desktop, tablet, and phone.

## Tech stack

- **Frontend:** React (Vite)
- **Backend:** Flask
- **LLM:** Groq API
- **File parsing:** `pypdf`, `python-docx`
- **URL scraping:** `trafilatura`
- **Document export:** `reportlab` (PDF), `python-docx` (Word)

## Getting started

### Backend

```bash
cd backend
python -m venv venv
./venv/Scripts/activate   # or `source venv/bin/activate` on macOS/Linux
pip install -r requirements.txt
cp .env.example .env      # then add your GROQ_API_KEY
python app.py
```

Runs on `http://localhost:5000` by default. See `.env.example` for all
configuration options (CORS origin, debug mode, host/port, and the
trusted-proxy settings needed once deployed behind a real reverse proxy).

### Frontend

```bash
cd frontend
npm install
cp .env.example .env       # adjust VITE_API_URL if the backend isn't local
npm run dev
```

Runs on `http://localhost:5173` by default.

## Security notes

This project includes basic production hardening: per-IP rate limiting, an
SSRF guard on the job-URL fetcher (blocks requests to private/internal
addresses, including via redirects), file-upload safeguards against
decompression bombs and malformed files, and a production WSGI server
(`waitress`) with proxy-aware IP detection for correct rate limiting once
deployed behind a real reverse proxy.

Still ahead of any public deployment: HTTPS (typically provided by the
hosting platform), security response headers, and error monitoring.
